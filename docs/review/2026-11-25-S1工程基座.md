## 3. 跑出来的两个真问题

### 3.1 `docs/sql/schema.sql` 落后模型 3 张表

迁移从**模型**生成后对比：`schema.sql` 只有 27 张，缺 `assistance_requests`（A-9 新增）、
`report_templates`、`match_ai_reviews`。说明 A-9 加表时没有人同步这份 DDL——
而它正是原计划里「0001_init 的基线」。若照它写迁移，会漏掉三张表且当场发现不了。

**结论：以模型 + Alembic 为唯一真相**，`schema.sql` 后续应由迁移导出或直接废弃。

### 3.2 `alembic.ini` 不能写中文注释

`configparser` 用系统 locale 读 ini，Windows 上是 GBK：只要 ini 里有中文，
`alembic` 启动就报 `UnicodeDecodeError: 'gbk' codec can't decode byte 0x8c`，
报错位置与真实原因毫不相干。已把 ini 改为纯 ASCII，并加测试 `test_alembic_ini_is_ascii_only` 卡死。

## 4. 尚未验证（不能算完成的部分）

| 项 | 为什么没验 | 怎么验 |
| --- | --- | --- |
| `docker compose up` 全栈 | 本机**没有 Docker**（`docker: command not found`） | 有 Docker 的机器上 `docker compose up -d`，看 3000/`elder` 与 8000/`health` |
| standalone 产物 | 本机账号**无创建符号链接特权**（`WinError 1314`），`next build` 开 standalone 就 EPERM | 同上，容器内构建即验证；或开启 Windows 开发者模式后 `NEXT_OUTPUT=standalone pnpm build` |
| GitHub Actions 是否真绿 | 还没 push，远端未跑过 | 推分支后看 PR 上三条检查 |

**这三项不写「已完成」**：配置写了没跑过，和没写一样危险——`schema.sql` 那件事就是证据。
