## 1. 起点核对：计划表写的和代码里的不是一回事

计划表写的是「冲突检测扩展到主诉 / 用药 / 既往史」，读代码后发现三件事，比原来估计的多：

| 读到的事实 | 位置 | 对本次范围的影响 |
| --- | --- | --- |
| 检测只比一类：对话症状 ∩ 量表关注症状，且量表结果正常 | `services/dialogue.py` `detect_conflicts` | 不是「扩展」，是「从一类做到四类」 |
| `conflict_flags[].field` 恒为 `"symptoms"`，前端直接把它拼进老人可见文案 | `elder/chat/page.tsx` | 老人看到的是「symptoms：…」，等于没说 |
| **画像的 `conditions` / `medications` / `chief_complaint` 从来没被写入过** | `_update_profile` 只累积 `symptoms` | 不补数据来源，用药与既往史两类规则写了也永远返回空 |

第三条是这次最关键的发现。只在 `detect_conflicts` 里加两条 `for` 循环，测试能过、功能等于零——因为画像相关字段恒为空，没有任何输入能与对话比对。所以本次先行补齐「从哪里拿到这三类信息」，再谈检测。

---

## 2. 真实缺口

### 2.1 听不懂否定

冲突检测的前提是能区分肯定与否定：

- 「我没有高血压」不是「我有高血压」；
- 「氨氯地平已经停了」不是「还在吃」；
- 「从来没头晕过」不是「头晕」。

原来的 `extract_symptoms` 只看词表是否命中，所以**否认也会被记成阳性**：老人说「我没有头晕」，`dizziness` 照样进画像，后续匹配、报告、定期评估全都跟着错。这是一个既有的、静默的错误，A-8 顺手修掉。

### 2.2 主诉没有落地

契约里 `chief_complaint` 的结构早就定了（`text / onset / site / nature / severity / course / associated`），但对话这条路一次都没写过它。没有主诉，「主诉与后续描述不一致」这一类就无从判定。

### 2.3 医护端看不到冲突

`conflict_flags` 会落进 `dialogue_turns`，也会由 `/dialogue/sessions/{id}` 带出来，但医护端**没有任何展示位**。冲突检测的唯一价值是交人复核，医护看不到等于没做。

---

## 3. 做了什么

### 3.1 否定 / 停用表述抽取（`extract_negations`）

规则实现，不引入模型。理由：冲突标记要能解释「凭什么标」，也要能写成断言；模型判断无法回归。

三条边界是刻意的：

| 边界 | 反例 | 处理 |
| --- | --- | --- |
| 否定只作用于**本分句** | 「没有高血压，但是头晕」 | 按标点切分句 |
| 否定词与目标词之间**只允许虚词**（≤3 字） | 「不想吃饭还腹泻」 | 距离上限，避免把后面的症状也算成否认 |
| 停用词前有「不能/不敢/别」时**不算停用** | 「氨氯地平不能停」 | 医嘱不是停用声明 |

病名做型别前缀容忍：画像记「2 型糖尿病」，老人只说「糖尿病」，按全名找会**整类漏判**。

### 3.2 四类冲突（`detect_conflicts`）

| `kind` | 判定 | `severity` |
| --- | --- | --- |
| `symptoms` | 对话症状 ∩ 量表关注面，量表结果正常 | `warn` |
| `complaint` | 主诉里说过的症状，后续被明确否认 | `info` |
| `medication` | 画像记录在用的药，对话说已停用 | `warn` |
| `history` | 画像里的既往史，对话里被否认 | `warn` |

`complaint` 定为 `info` 而不是 `warn`：老人复述病情时前后措辞不同很常见，不该按高危项占用医护注意力。

新增字段 `kind` / `severity` / `title` / `profile_value` / `evidence`，**保留 `field` 与 `scale_value`**：旧前端按这两个拼提示，改结构不能把老页面打空。

### 3.3 画像写入修正

- 被明确否认的症状**不入画像**（见 §2.1）；
- `chief_complaint` 在第一轮**抽到症状**的发言写入一次，后续不改写；「你好」不会成为主诉；
- 病史 / 用药的读取兼容 `list[str]` 与 `list[dict]` 两种历史形态——契约写的是对象数组，但早期种子数据存的是裸字符串。

### 3.4 前端

- `lib/conflicts.ts`（新增）：冲突文案的唯一出口。老人端与医护端需求相反，所以出两个函数——`elderConflictLine` 只出人话（不暴露英文键，也不用「不一致/冲突」这类判断词，老人听了只会紧张）；`groupConflicts` 按类别分组去重。
- 老人端对话页：提示改为「有几处信息需要医生核对，已经替您记下来了」+ 逐条人话。
- 医护端匹配 tab：新增「信息冲突」区块，`warn` 组在前，每条带原句片段，底部注明「只标记不覆盖」。

| 项 | 结果 |

| 后端 `pytest -q` | **277 passed**（256 → +21） |
| 前端 `vitest run` | **59 passed**（47 → +12） |
| `tsc --noEmit` | 0 |
| `eslint --max-warnings=0` | 0 |
| `next build` | 通过（4.7s，13/13 页） |

新增用例分布：`tests/test_conflict_expand.py` 21 条（否定抽取 9、四类冲突 6、画像与落库 6），`src/lib/conflicts.test.ts` 12 条。

**其中 6 条是「不该报」的用例**，比「该报」更重要：

- 「不想吃饭还腹泻」不得把腹泻记成否认；
- 「糖尿病好多年了」不得报既往史冲突；
- 「氨氯地平不能停」不得报用药冲突；
- 没有任何矛盾时 `detect_conflicts` 必须返回空数组。

理由：冲突标记会被医护当真。误报两次之后，这个区块就没人看了，等于白做。

### 4.1 走查中发现并已修的两处

| 问题 | 发现方式 | 修法 |
| --- | --- | --- |
| 症状索引在**每个分句**里重建一次（113 条 + 排序） | 实测 25 分句输入单轮 1.42ms，随分句数线性增长 | 词表是静态文件 → `lru_cache` 并返回元组，索引提到分句循环外；实测降到 0.36ms |
| **纯否认句被记成主诉** | 用真实接口跑「我没有头晕」→ `chief_complaint = {text: "我没有头晕", symptom_codes: ["dizziness"]}` | 主诉只在含肯定陈述时写入，且 `symptom_codes` 排除被否认的码 |

第二条是**自相矛盾的误报**：写进主诉后，下一轮再说一次「真的没有头晕」，就会拿主诉跟本轮否认比对，报出「主诉说头晕、但对话否认头晕」——而两边是同一句话。已在 `test_denial_does_not_become_chief_complaint` 里钉住。

## 5. 刻意没做的

| 没做 | 原因 |
| --- | --- |
| 用模型做否定理解 | 无法回归、无法解释，且会让「标了但说不清为什么」成为常态 |
| 后置否定（「头晕？没有」） | 规则上容易与「头晕不需要卧床」混淆，误报率明显高于收益；先不收 |
| 自由抽取病名 / 药名 | 没有受控词表，错位匹配会把「二甲双胍」当成新病名；只对**已有记录**做否定判定 |
| 用药画像的录入入口 | 属医护端 / B 线职责。本次只让「有记录时能核对」，记录怎么来不在 A-8 范围 |
| 据冲突自动更正任一方 | 红线：AI 不下结论。四类命中都不改量表、画像与计分 |
| 把 `conflict_flags` 接进质控指标 | 需要先有误报率基线，现在接进去等于用未校准的数字做考核 |

## 7. 已知限制

1. **否定识别是规则近似**。口语变体（「血压不算高」「头晕早好了」）识别不到，会漏报。设计取向是**宁可漏报也不乱报**——乱报会让医护不再相信这个标记。
2. **用药类目前难以真实触发**：画像 `medications` 没有录入入口，只有种子数据。规则与测试都已就绪，等录入入口补上即可生效。
3. **主诉只有文本**，`onset / site / nature` 仍是空串，未做结构化抽取——那属于 A-4（口语化 / 结构化）的范畴。
