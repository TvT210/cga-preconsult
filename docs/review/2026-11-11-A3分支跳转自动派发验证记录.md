## 2. 接口实测（独立临时库，未污染开发库）

### 2.1 巴氏指数筛查阳性 → 自动派发两条待办

作答：`B1-09 = 10`（< 15，行走不能独立）、`B1-07 = 5`（< 10，如厕自理受限），其余条目按常规作答后 `finish`：

```json
[
 { "branch_code": "B1-B1", "source_scale": "B.1", "target_scale": "B.3",
   "target_name": "简易体能状况量表（SPPB）",
   "reason": "平地行走不能独立，建议加做简易体能状况量表（SPPB）实测体能。",
   "status": "dispatched", "skip_reason": "", "session_id": 2, "session_status": "in_progress" },
 { "branch_code": "B1-B2", "source_scale": "B.1", "target_scale": "B.11",
   "target_name": "尿失禁问卷（ICIQ-SF）",
   "reason": "如厕自理受限，建议加做尿失禁问卷（ICIQ-SF）。",
   "status": "dispatched", "skip_reason": "", "session_id": 3, "session_status": "in_progress" }
]
```

要点：`session_id` 可直接跳转进入；`session_status` 为 `in_progress`，即**空壳待办**，不含任何作答与结论。

### 2.2 重复 `finish` → 幂等，不重复派生

```
[('B1-B1', 'reused', 2), ('B1-B2', 'reused', 3)]
```

会话 id 与首次完全一致，库里 `dispatched_from_id` 指向该会话的记录仍是 2 条。

### 2.3 SPPB 建议回派巴氏指数 → 环防护生效

在派发出的 SPPB 中作答 `B3-04 = 6_21_8_70`（2 分，命中 `lte 2`）：

```json
[{ "branch_code": "B3-B1", "source_scale": "B.3", "target_scale": "B.1",
   "reason": "步速明显减慢，建议加做基本日常生活活动能力评估，明确失能程度。",
   "status": "skipped", "skip_reason": "cycle", "session_id": null }]
```

链上已有 B.1（就是它的来源），因此不再派生。若不做这层防护，这条边会与 `B1-B1` 构成无限循环。

## 5. 遗留与注意事项

1. **前端需要真机/浏览器点一遍。** `tsc` 与 `eslint` 只能证明类型和规范，实际跳转与按钮文案需人工确认；`next build` 在本机受限（见 A-2 验证记录 §5），已交由用户在本地终端执行。
2. **派发口径依赖题库评审。** 分支的触发阈值来自题库 `branches.when`，在量表通过医护评审（A-1）前，这些阈值同样属于待确认内容；当前派发只是「按标准原文整理的建议」，不构成诊断。
3. **staff 端不显示派发入口。** 结果页属老人端（`/elder/scale/[id]`），依赖 `user.patient_id` 恢复会话；staff 代答场景需在医护端另做入口，属后续事项。
