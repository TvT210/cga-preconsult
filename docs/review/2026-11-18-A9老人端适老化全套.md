## 2. 前端

### 2.1 字号与主题都走「作用域 + CSS 变量」

```
`div.elder-theme[data-elder-scale=standard|large|xlarge]`
        ↓  --e-fs-base / --e-fs-2xl / --e-btn
`.text-elder` `.text-elder-2xl` `.min-h-btn` 等既有语义类被重映射
```

- 组件源码零改动即可换字号，`QuestionCard` / `BigButton` / `AppShell` 一行没为字号改；
- **默认档取值与改造前完全一致**（18 / 20 / 22 / 26px，行高 1.8 / 1.7 / 1.6 / 1.5），不切档时版式不变；
- 医护端 `.theme-clinical` 与本作用域互不包含，两侧 token 各自独立。

配色对比度全部实测（`python tools/check_elder_contrast.py`，14 组）：

| 组合 | 比值 | 要求 |
| --- | --- | --- |
| 主色 `#0f766e` / 白底 | 5.47 | ≥ 4.5 |
| 白字 / 主色按钮 | 5.47 | ≥ 4.5 |
| 白字 / 主色深（悬停） | 7.58 | ≥ 4.5 |
| 白字 / 暖橙按钮 `#c2410c` | 5.18 | ≥ 4.5 |
| 弱化文字 `#64748b` / 白底 | 4.76 | ≥ 4.5 |
| 正文 `#1a1a1a` / 白底 | 17.40 | ≥ 7 |

暖橙没有选更暖的 `#ea580c`：配白字只有 3.56:1，过不了 AA——暖橙只能当按钮底色用深一档。

### 2.2 一步一屏

量表页同屏内容从「题目 + 语音条 + 代答设置 + 4 个按钮 + 两段说明」压到
「进度头 + 语音条 + 题目 + 上一题/下一题」。跳过、暂停、家属代答设置收进
「其他操作：跳过、暂停、家属代答」折叠区；续填代答会话时自动展开，代答人能看到自己是谁在答。

### 2.3 语音条

- 改为量表页**吸顶常驻**（`sticky top-2`）：往下翻题目时朗读按钮始终可点；
- 人声选择：`speechSynthesis.getVoices()` 过滤中文 → 同名去重 → 本机音色优先 → 普通话优先；
  只剩一个中文音色时**不显示选择器**，改为一句话说明（选择器只有一个选项等于没有选择）；
- 语速 0.6~1.2 / 0.1 步进沿用旧口径，但改为**记在偏好里**：老人调过一次，翻到下一题不会变回默认；
- 自动朗读为开关，默认关。

### 2.4 吸底条

`ElderDock` 挂在老人端 layout，所有页面都在：左边字号三档、右边「呼叫工作人员」。
点呼叫 → 拉 `/elder/support` 与「有没有还没人来的呼叫」→ 落一条请求 → 老人看到
「已通知，工作人员还没到」，可再叫一次。

**正文留白按实测高度走**：写字数固定 `padding-bottom` 会在「特大字号 + 360px」翻车——
那时按钮折成三行，吸底条从 130px 涨到 **216px**，正文最后一段正好被压住。
改用 `ResizeObserver` 把实测高度写进 `--e-dock-h`，`main` 的留白按它算
（实测 360px/特大：条 216px、留白 240px）。

### 2.5 代答入口

`/elder/proxy`：填代答人姓名与关系 → 选量表 → 有未完成会话则 `PATCH /assessments/{id}/responder`，
否则 `POST /assessments` 带 `responder=proxy` → 跳转量表页。
**填写入口仍只有量表页一个**，不复制第二套答题逻辑。

## 3. 后端（求助通道）

| 表 | 字段 |
| --- | --- |
| `assistance_requests` | `patient_id` / `session_id` / `question_code` / `note` / `status`（pending、handled）/ `created_by` / `handled_by` / `handled_at` / `handle_comment` |

新文件 `backend/app/api/elder.py`，五个端点（契约 CA-20261118-04）：

- `GET /elder/support`：机构电话取自配置 `CGA_ELDER_HELP_PHONE`，**未配置返回空串**，前端如实提示现场求助；
- `POST /elder/assistance`：elder 角色的 `patient_id` 由服务端定，请求体里塞别人的一律忽略；
  会话必须属于本人（否则 400）；
- `GET /elder/assistance`：老人只看本人；
- `GET /assistance`（staff+）：默认只看 pending，带患者姓名（一次查库补齐，不逐条查）；
- `POST /assistance/{id}/handle`：重复处理不报错，但**保留首次处理人与时间**。

### 为什么不复用 `alerts`

就医提醒由匹配结论产生，是质控指标（提醒量、误报率、响应率）的分子分母。
把「老人不会填第 3 题」混进去，等于自己把指标做脏。两张表、两条链路，成本很低。

### 为什么不做自动派单

系统里没有排班、没有在岗、没有科室归属，派给谁都是编的。只标「待处理」，由现场人员认领。

## 4. 医护端

### 顺带修掉的两个真问题

1. **打印把标题也删了**：初版 `@media print` 用 `.elder-theme header { display:none }`，
   而 `PageHeader` 组件本身也是 `<header>`，于是「我的报告与提醒」标题一起消失。
   改为只隐藏 `.app-shell-header`（顶栏加了该类）。
2. **报告页在 360px 下横向溢出 261px**：`renderScalar` 把对象渲染成 `JSON.stringify`，
   一长串无空格的 JSON 把 `dd` 撑开。加 `min-w-0 break-all` 后归零；
   同时把报告抬头常见的 19 个英文字段补进中文映射（原来老人打印出来是 `patient_id 1`）。

## 6. 老人端视觉基线口径变了（需要在站会上说清）

`tools/verify_elder_unchanged.py` 的语义从「对二期基线逐像素不变」改为
「**对 A-9 新基线**不变」。脚本判据本身没动，A-9 合入后需按新视觉重取基线截图与 DOM 签名。
`docs/frontend/医护端视觉规范.md` 的检查项同步改口径。

这不是放宽要求：它防的是「线 B 改医护端把老人端串色」，而不是禁止老人端自己演进。
