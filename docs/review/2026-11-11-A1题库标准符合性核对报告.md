## 1. 这份报告做了什么、没做什么

**做了**：以标准 PDF 的附录 B 原文为准，把 21 张量表的**条目、分值、判读分界值、分支阈值**逐张比对，发现并修正了 3 处实质偏差。

**没做**：**这不是临床评审**。临床评审要由具备资质的医师／护士确认「这套问法在真实老人身上问得对不对、阈值在临床上认不认」，属于专业判断。本报告只做**文本符合性核对**——原文写了什么、我们录的是什么、有没有对不上的地方。

因此 21 张量表的 `review_status` **全部保持 `draft_pending_medical_review` 不变**。任何情况下都不应把本报告当作 approved 的依据。

## 2. 核对方法

1. 用 PyMuPDF 提取标准 PDF 全部 29 页文本（该 PDF 有完整文本层，表格与「注」均可读）；
2. 按 `表B.x` 切块，逐张对照题库 JSON 的 `sections[].questions[].options[].score` 与 `scoring.levels.config.levels[]`；
3. 对「选项档位数少于原文」的题目单独复查（这类最容易在录入时被简化）；
4. 修正后补测试钉住边界，防止回退。

## 4. 三处修正

### 4.1 B.2 工具性日常生活活动：选项被模板化，导致系统性低估

**原文**：表B.2 的 8 个项目各有 3~5 个具体行为档位，其中第 2、4、5、6、8 项**存在「需部分协助仍记 1 分」的档位**，第 4 项「家务维持」更是前四档全部记 1 分，只有「完全不能做家务」才记 0 分。

**原实现**：8 道题统一成「可独立完成（1 分）／需部分帮助（0 分）／不能完成（0 分）」。

| 项目 | 原文给 1 分的档位（节选） | 原实现判分 |
| --- | --- | --- |
| 使用交通工具 | 独立坐出租并安排路线、他人陪伴下能坐公交 | 0 分 ❌ |
| 家务维持 | 简单家务、简单家务但不够整洁、**所有家务需别人协助** | 0 分 ❌ |
| 洗衣服 | 只清洗小件衣物或部分衣物需协助 | 0 分 ❌ |
| 使用电话 | 仅可拨熟悉号码、仅会接不会拨 | 0 分 ❌ |
| 处理财务 | 日常购买可以，银行往来需协助 | 0 分 ❌ |

**影响**：一位「家务全需协助、只会接电话、只能拨熟悉号码、洗小件衣物」的老人，按原文应得 5 分（中度受损），旧实现只得 0~1 分（严重依赖）。**这是把人往重里判，会虚增照护负担**。

**修正**：8 题全部按原文重建选项与分值，`notes` 记录「不可按能否独立二分为 1/0」。

**测试**：`test_b2_partial_help_still_scores_one` 逐项钉住分值序列，并用一组「需部分协助」作答断言总分 5 分、等级「中度受损」。

### 4.2 B.18 营养风险筛查：结构不符，缺年龄加分

**原文**：表B.18 分两步——先做表B.18-1 初筛 4 项（BMI＜20.5、3 个月体重减轻、1 周摄入减少、疾病严重），**任一项为「是」**才做表B.18-2 终筛；终筛总分 = 营养状态受损（0~3）+ 疾病严重程度（0~3）+ **年龄≥70 岁加 1 分**，满分 7 分。

**原实现**：只有 3 个计分项——体重下降（0~2）、进食量减少（0~2）、疾病严重程度（0~3）。

| 差异 | 后果 |
| --- | --- |
| 营养状态受损被拆成「体重」+「进食量」两项，上限变 4 而非 3 | 两项都阳性时虚高 1 分 |
| **完全没有初筛环节** | 所有人都直接做终筛，与标准流程不符 |
| **没有年龄加分** | 70 岁以上老人少算 1 分，可能漏判营养风险 |

**修正**：重建为 9 题——初筛 4 题（0 分记录）、终筛 3 题（营养受损 0~3、疾病严重 0~3、年龄 0/1）、身高体重 2 题（记录，不参与计分）。终筛三题带 `when` 门槛：初筛全「否」时不出现、不计分。

**测试**：`test_b18_three_part_scoring_includes_age_bonus`（同为营养 2 分，≥70 岁得 3 分判「存在风险」，＜70 岁得 2 分判「未达」）、`test_b18_screening_gate_skips_final_section`。

### 4.3 B.13 睡眠障碍：分级区间重叠，6 分落在哪一档没有定论

**原文注2**：「0～3 分，无睡眠障碍；4～6 分，可能有睡眠障碍；**≥6 分**，存在睡眠障碍」。

标准自身在 6 分处矛盾（4~6 与 ≥6 重叠）。原实现照录为 `4~6` 与 `6~24`，靠 `level_map`「首个命中生效」让 6 分落入「可能存在」，并在 `notes` 里声明了这一取舍——**这个判断本身是站得住的**（保守方向，且已留痕）。

但它有两个问题：一是区间在数据上确实重叠，换一种匹配实现就会变；二是「6 分算什么」只存在于注释里，没有体现在配置上。

**修正**：不动判读口径，只把区间写成互不重叠的 `4~6` 与 `7~24`。6 分仍判「可能存在」、7 分及以上判「存在」，**行为与原来完全一致**，但重叠从数据层面消除，`notes` 也改为明确说明「保留原口径 + 区间去重」。

**测试**：`test_b13_overlap_removed_without_changing_ruling` 同时钉住 6 分与 7 分；另新增全库校验 `test_level_map_ranges_never_overlap`，21 张表逐张验证区间互不重叠——这类问题不会再无声无息地出现。

## 5. 顺带修改的引擎行为

`scoring.evaluate_scale` 原先在「计分条目全被 `when` 过滤」时直接 `return`，导致等级为空。这对 B.15 未选插管状态是合理兜底，但 B.18 初筛全否是**合法阴性结论**，不该没有等级。

改为记录提示后继续走分级：B.18 因 0 分落在 `0~2` 区间而正常判「未达营养风险」；B.15 因 0 分不在 `3~12` 区间，仍走「分值未落入任何判读区间」的兜底，行为不变。全部 220 条测试通过，无回归。

2. **`review_status` 仍全部为 draft**。本报告不能替代临床评审。
3. 核对的判断依据是标准文本，**不排除我对个别表述的理解偏差**，尤其 B.20 的年龄分支、B.12 的计分取舍两处。
