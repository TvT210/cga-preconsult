## 2. 改了什么

### 2.1 Provider 层：把「流」接到模型、把「思考」拦住

`packages/medagent/llm.py`

- `MockProvider.stream_chat` / `OpenAICompatibleProvider.stream_chat`：两者都按块产出文本。Mock 每 6 字切一刀，是为了让「增量拼接 == 全文」这条测试真的在验证拼接，而不是一次吐完等于没流式。
- `ThinkStreamFilter`：流式剥离 `<think>…</think>`。难点是标签会被切在两个 chunk 中间（`"<thi"` + `"nk>…"`，甚至一个 chunk 只有 `"<"`）。处理方式是把**可能构成标签前缀的尾巴**暂存到下一块再判，其余照常吐出——这样既不会让老人看到半截标签，也不会把正文里「血压 < 140」的 `<` 吞掉。未闭合的思考块在流结束时丢弃，与非流式 `strip_think` 的行为一致。
- `stream_chat()` 统一入口：Provider 没有 `stream_chat` 时退化为一次性 `chat`，新增 Provider 不必同时实现两个方法；**一个字都没产出**时抛 `LLMEmptyResponse`，交给调用方给「请再说一遍」，而不是把空串当回答。

### 2.2 服务层：流式与非流式共用一条落库路径

`app/services/dialogue.py` 把原来一整个 `run_dialogue_turn` 拆成三段：

| 函数 | 职责 |
| --- | --- |
| `prepare_turn` | 取历史、解析提示词、取 Provider → `TurnContext` |
| `finalize_turn` | 抽取症状、安全提示、冲突标记、写两条 turn + `model_runs`、更新画像、组装响应体 |
| `run_dialogue_turn` | 非流式：`prepare` → `timed_chat` → `finalize` |

这样两条路径只有在「文本怎么产生」上不同。**这是「字段与非流式一致」这条验收标准能成立的结构性原因**——不是靠两处各写一遍再对齐，而是压根只有一份。

顺带修了一处不一致：原先 `model_runs.prompt_version` 记的是 `resolve_prompt` 解析出的版本，而响应体里写死的是常量 `DIALOGUE_PROMPT_VERSION`。提示词在后台改过之后，返回给前端的版本号是假的。现在统一用解析出来的版本（默认值相同，因此现有行为不变）。

### 2.3 接口层：SSE 端点与中断语义

`app/api/dialogue.py` 新增 `POST /dialogue/sessions/{id}/messages/stream`。

- 会话存在、权限、内容非空三项校验全部在**推流之前**完成。一旦开始推流状态码就固定 200，参数错误只能用事件表达，不如提前用 4xx 挡掉。
- 命中急症规则时，`safety_note` 作为**第一帧**发出，不等模型把话说完。这是安全优先的取舍：老人说「胸口压得慌」，红色警告不该迟到十几秒。
- 流中途失败但**已经出过字**：保留已生成内容并标 `interrupted: true`，不替换成兜底话术——前后文会自相矛盾，医护也会误当成完整回复。一个字都没出时才用兜底话术。
- 客户端断开（关页面、切网络、点停止）：`finally` 里把已说出的部分落库并标记中断；一字未出时也保留这条用户消息。老人说过什么不能因为断线就丢。

## 3. 实测

### 3.1 事件序列（真实 HTTP，curl -N）

```
data: {"reply": "您说的头晕大", "done": false}

data: {"reply": "概持续多久了", "done": false}

data: {"reply": "？有没有伴随", "done": false}

data: {"reply": "视物模糊、说", "done": false}

data: {"reply": "话不清或者手", "done": false}

data: {"reply": "脚无力？", "done": false}

data: {"reply": "您说的头晕大概持续多久了？有没有伴随视物模糊、说话不清或者手脚无力？",
       "extracted": {"symptoms": [{"code": "gait_instability", "term": "走路发飘", "confidence": 0.85, "source": "dialogue"},
                                  {"code": "dizziness", "term": "头晕", "confidence": 0.85, "source": "dialogue"}],
                     "proxy": {}},
       "safety_note": "", "conflict_flags": [],
       "disclaimer": "本系统不提供诊断与用药建议，结果仅供参考，不构成诊断，请及时咨询医生。",
       "model": "mock-deterministic-v1", "prompt_version": "0.1.0-draft",
       "interrupted": false, "done": true}
```

响应头：

```
HTTP/1.1 200 OK
cache-control: no-cache, no-transform
x-accel-buffering: no
content-type: text/event-stream; charset=utf-8
transfer-encoding: chunked
```

要点：**没有 `content-length`，是 `chunked`**。`TestClient` 会把整条流读完再返回，看不出这一点，所以专门起了真实 uvicorn 验证。

### 3.2 急症提示前置

输入「胸口压得慌，喘不上气」，首帧即为：

```json
{"safety_note": "胸口不适可能是急症信号，请立即前往急诊或拨打 120，不要自行服药。", "done": false}
```

无 `reply` 字段，不与正文混在一起。收尾帧里仍带同样的 `safety_note`，前端刷新会话后照样能显示。

### 3.3 字段一致性

同一个输入分别走流式与非流式，收尾帧去掉 `done` 之后与响应体**逐字段相等**（`set(streamed) - {"done"} == set(plain)`，且每个键的值相同）。测试 `test_stream_final_fields_match_non_stream` 钉住这条。

### 3.4 中断

生成器在只吐出一帧后 `close()`，库里结果：

```
user      | 我最近腿软
assistant | （已说出的那部分）   extracted = {"interrupted": true}
```

## 4. 前端

- `src/lib/api.ts` 新增 `streamDialogueMessage()`：`fetch` + `ReadableStream` 解析，不走 `api.get/post`（后者会把响应读成文本）。SSE 分隔用 `/\r?\n\r?\n/` 兼容代理插入的 `\r`；401 与统一封装同样处理；**主动中断返回 `null`**，不抛错——老人点「停止」是正常操作，不该弹错误。
- `elder/chat` 页：历史记录 + 这一轮临时气泡合成一条列表渲染，服务端返回后整体替换，老人看不到「先说了一大段又消失」的空窗。发送中按钮变「停止」。
- 已经说出一部分才失败时保持原样并标「这条回复没有说完，已按原样记录」；一点没出则把内容还回输入框，老人不用重打。
- 端点不存在或服务端 5xx 时降级为原非流式接口，保证对话能继续。
- **没有做「打字机」节流**：真实模型的 chunk 本身就带间隔，按到达即渲染最自然；再叠一层定时器只会在网络抖动时让文字落后于服务端。mock 演示时会显得一下跳完，那是 mock 没有真实延迟的特征，不是前端问题。

## 6. 已知未解决

1. **`next build` 未跑**：本机环境限制，需本地终端确认一次。本次改了 JSX。
2. **老人端每次进页面都会新建一个对话会话**（`bootstrap` 里 `POST /dialogue/sessions`），所以离开页面再回来看不到刚才的历史。这是既有行为，不在 A-7 范围内，但会削弱「停止后回来接着看」的体验。要修得先定「如何选择当前会话」的语义（最近一条？当天第一条？），属于产品决策。
3. **语音播报只在整段结束后触发**（`VoiceBar` 拿的是 `lastReply`）。边生成边播报体验更连贯，但需要 TTS 与流式文本的协同，本轮未做。
4. **`model_runs.latency_ms` 记的是整轮耗时**，没有首字延迟（TTFT）。要做成本与体验预算（B-9）时需要 TTFT 分位，届时补字段。
