# 一期全模块骨架搭建计划（2026-11-04）

> 依据：`docs/项目构想总需求.md`（需求基线）、根目录 `AGENT.md`（约定与红线）
> 目标：搭出「预问诊 → 量表采集 → 自动计分判读 → 综合评估报告 → 多候选疾病匹配与分级提醒」主线可跑通，
> 并把需求文档中的其余模块（适老化、AI 对话、定期评估、随访、权限、审计质控、系统管理）以**可运行骨架**铺开。

## 0. 本次范围与取舍

| 模块 | 本次交付形态 | 说明 |
| --- | --- | --- |
| 用户与权限 | 可运行 | JWT 登录、4 类角色、RBAC 依赖、审计留痕 |
| 知情同意 | 可运行 | 采集前必须落同意记录，可撤回 |

| 自动计分与判读 | 可运行 | 规则可解释（结论回溯到题目与规则条目）、缺项标「待人工确认」、不硬编码阈值 |

| 匹配提醒 | 可运行 | Top-N（≥3）候选、匹配度 + 参考概率、命中／缺失／排除依据、四级提醒、阈值可配置留痕 |
| 随访管理 | 骨架 | 计划、到期复评、趋势接口、异常升级入口 |
| 审计与质控 | 骨架 | 审计日志写入、质控指标聚合接口 |
| 系统管理 | 骨架 | 用户/角色/量表版本/阈值/提示词模板管理入口 |

**取舍说明**：题库与疾病库的医学条目必须以 WS/T 888—2026 附录 B 原文与专家评审为准。
本仓库内 `量表评估国家标准.pdf` 未随需求资料提供，因此本期预置条目属**待评审草稿**，
统一带 `review_status: draft_pending_medical_review`，需医护核对原文后经审批发布（红线 1、5、7）。

## 2. 关键设计决策

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| D1 | 计分规则解释器，两阶段：先算分（sum/count_positive/max），再判级（level_map），另挂 condition 标记 | 可解释、可回溯、阈值不硬编码 |
| D2 | 题库以 JSON 存 `docs/structured/assessment-scales/`，代码入库可版本化 | 标准符合性需可追溯、可评审 |
| D3 | 数据库同时支持 PostgreSQL（生产）与 SQLite（本地演示） | 本机 Docker 守护进程未运行，不能阻塞主线 |
| D4 | AI 对话走 `LLMProvider` 抽象 + `mock` 实现，接口与真实模型一致 | 无 Key 也能演示；换模型不改业务代码 |
| D5 | 匹配引擎纯规则（症状倒排 + 加权 + 鉴别扣分 + 阈值），不引入概率模型 | 一期要求可解释、可配置、可审计 |
| D6 | 阈值、权重、提示词全部入库，修改留痕并需审批标记 | 红线 5、7 |

## 4. 验收标准

1. `backend` 测试全绿（计分、判读、匹配、鉴权、报告导出）。
2. `frontend` 生产构建通过。
3. 本地一条命令起后端 + 前端，浏览器可完成：登录 → 建患者 → 预问诊 → 采集 1 张量表 → 自动判读 → 生成报告 → 触发匹配 → 看到分级提醒。
4. 报告可导出 Word/PDF，结论可回溯到题目与规则条目。
5. 所有对外文案使用「匹配度／参考概率」，附「仅供参考，不构成诊断」声明。
6. Git：`dev` 分支 + 功能分支历史清晰，远程仓库 `cga-preconsult`（公开）已推送。
