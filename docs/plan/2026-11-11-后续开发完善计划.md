## 4. 后续顺序建议

### 4.1 里程碑（4 个，两条线并行）

```
M1（11/11~11/22）工程基座可交付
     B: Alembic + CI + Dockerfile + 契约校验        A: 前端测试骨架 + 实测项录入组件
     出口：任何人 clone 后一条命令起环境，PR 自动跑测试

M2（11/23~12/06）质量可量化
     B: 标注集 + 阈值校准 + 评测脚本 + 时序表      A: SSE 流式 + 分支跳转 + 冲突检测扩展
     出口：Top-3 召回率与误报率有数字，阈值有依据

M3（12/07~12/20）AI 闭环上线
     B: 模型可观测 + 提示词运营 UI + 成本预算 + 安全闭环
     A: 量表评审推进 + 老人端体验
     出口：AI 建议可观测、可运营、可回滚；数据可导出可审计

M4（12/21~12/31）发布与收尾
     全员：发布流程 + 版本快照 + 回归全量测试 + 文档收口
     出口：main 分支从 dev 同步，版本可回滚
```

### 4.2 关键路径（决定项目能不能按时收口）

```
医学评审（量表 21 张 + 病种权重）─→ 启用「立即就医」自动触发 ─→ 匹配准确率达标
        ↑ 阻塞，需要导师/临床老师排期
```

> **这是全项目唯一的硬阻塞**，且**不在我们俩手里**。建议本周就去敲定评审人与时间，
> 否则 M2 的阈值校准与 M3 的自动提醒都缺「评审通过」这个前提。

### 4.3 建议的协作节奏（沿用 §5.2）

- 每天 15 分钟站会，只同步「昨天卡在哪 / 今天要什么」
- 每周五一次进度对表，更新本计划的勾选状态
- 每个 Sprint 第一天复核一次冻结契约（`docs/api-contract.md`）

## 5. 验收标准（DoD）

| 里程碑 | DoD |
| --- | --- |
| M1 | `docker compose up` 起全栈；PR 上 CI 全绿；迁移可升可回；A/B 都有前端测试 |
| M2 | 标注集 ≥200 条入库；校准脚本出曲线；Top-3 召回 ≥85%；Top-1（clear 组）≥75% |
| M3 | 真实模型跑通且**可观测**（空回复率、降级率、耗时分位可见）；提示词可运营可回滚；导出脱敏 + 审计齐全 |
| M4 | 全量测试绿；报告与提醒口径一致；`main` 与 `dev` 同步；文档与代码一致 |

**红线（不可让步）**：AI 不下诊断结论；只出现「匹配度」「参考概率」；人工复核强制项不自动通过；老人端视觉不回退；密钥不入库。

## 6. 风险与预案

| 风险 | 影响 | 预案 |
| --- | --- | --- |
| **医学评审排期拖** | 阻塞 M2/M3，自动提醒不敢开 | 本周敲定评审人；先按 draft 跑通全链路，评审通过后一键开 |
| 推理模型空回复 / 延迟高 | 老人端等待过长 | 已做降级（请再说一遍）+ 限流 + 模型分级；P95 超预算自动切 highspeed |
| 无 CI，改代码易破 | 回归成本高 | M1 优先补 CI，之后每个 PR 必跑 |
| 无迁移，改表靠手工 | 生产不可控 | M1 Alembic；之后任何加表走迁移 |
| A/B 都在改 `models.py` / `tailwind.config.ts` | 冲突 | 按分工表走「变更申请」；共享文件改动前后各跑一次视觉/契约自检 |
| 真实模型输出不稳定 | 复核质量波动 | 提示词版本化 + 评测集回归 + 失败降级；不达标就退回规则主导 |
