> 对应 `docs/plan/2026-11-11-后续开发完善计划.md` 的 **A-2**

## 1. 现象与根因

计划里写的是「缺实测录入组件」，实际排查后发现组件早就写好了（`QuestionCard.tsx` 有数字输入、计时器、单位显示），**问题出在三个断点上**，任一个没接通，计时器都不会出现。

### 断点 1：字段错位（`measure.unit` vs `unit`）

| 位置 | 现状 |
| --- | --- |
| 题库 JSON | `question.measure = { "unit": "s", "hint": "记录实际保持秒数（0~10）" }` |
| 前端读取 | `QuestionCard.tsx:43` → `Boolean(question.unit)`（顶层字段） |
| 后端返回 | `scales.py` 原样透传题库 JSON，未做展开 |

结果：`question.unit` 恒为 `undefined`，`isMeasured` 恒为 `false`。

### 断点 2：实测分档题的 `input_type` 是 `single`，走不到数字输入分支

全库 10 道带 `measure` 的题：

| 量表 | 题目 | input_type | 选项带 min/max | 性质 |
| --- | --- | --- | --- | --- |
| B.3 SPPB | B3-01~B3-05 | `single` | ✅ | 填秒数 → 按区间定档 |
| B.17 洼田 | B17-01 | `single` | ✅ | 填秒数 → 按区间定档 |
| B.7 耳语 | B7-01、B7-02 | `single` | ✅ | 填词语数 → 按区间定档 |
| B.12 便秘 | B12-01、B12-02 | `number` | ❌ | 纯记录，不计分 |

前 8 题是**实测分档题**：临床上是「测量 → 填数值 → 落档」，题库把它们表达为「带 `min`/`max` 区间的单选选项」。但前端 `QuestionCard` 只在 `input_type === "number"` 时渲染输入框，`single` 分支只渲染按钮组——所以即使修好 `unit`，这 8 题仍然只能手动点档位，等于没有实测录入。

### 断点 3：只填实测值时前端拦着不让过

`elder/scale/[id]/page.tsx` 的 `handleNext` 校验 `entry.value` 非空才放行。实测分档题正确的提交方式是 `value=null, measured=4.5`（后端 `_apply_answer` 已支持按区间自动定档），但前端会判为「未作答」并弹出提示。

### 附带发现（顺手修）

- `_session_payload` 的 `answers` 数组**没有返回 `measured`**，导致断点续填时实测值丢失（A-5 相关）。
- `_session_payload` 的 `sections` 与 `questions` 分别取自原始结构，若只展开一处会出现两套字段。

## 2. 设计原则

1. **不改题库、不改判读语义**：`measure` 是题库的规范字段，保留不动；只在**对外表示层**展开成前端可读的顶层字段。
2. **向后兼容**：新增字段全部为非破坏性追加，B 线现有代码不读这些字段则完全无感。
3. **档位判定只在后端发生**：前端可以本地预演「将记为哪一档」用于即时反馈，但提交仍只发 `measured`，档位由后端 `_band_for` 决定，避免两套判定逻辑漂移。
4. **兜底选项必须保留**：实测题都有「不能完成／不尝试」这类无法用数值表达的选项，UI 必须让评估人员能选。

## 3. 后端改动

### 3.1 新增 `backend/app/services/scale_presenter.py`

对外表示层，纯函数、无副作用、幂等：

| 展开字段 | 来源 | 含义 |
| --- | --- | --- |
| `unit` | `measure.unit` | 单位（秒／个／月），前端用于输入框后缀与朗读 |
| `unit_hint` | `measure.hint` | 施测提示，前端作为输入框下方的操作说明 |
| `banded_input` | 计算：`input_type=="single"` 且存在带 `min`/`max` 的选项 | `true` 表示「可填数值由后端自动定档」，前端据此渲染实测录入区 |
| `fallback_options` | 计算：无 `min`/`max` 的选项 value 列表 | 「不能完成」类兜底选项，前端单独渲染 |

`measure` 原字段保留不动。返回深拷贝，避免污染 `get_scale` 的缓存对象。

### 3.2 `backend/app/api/scales.py`

`GET /scales/{code}` 的返回值经 `present_scale()` 处理；`item_count`、`ready_for_scoring` 等计算仍基于原始结构。

### 3.3 `backend/app/api/assessments.py`

- `_session_payload` 的 `questions` / `sections` 统一经 presenter 处理（保证两处字段一致）；
- `answers` 数组补 `measured` 字段（修断点续填丢值）；
- 内部逻辑（`_questions`、`_question_table`、`_band_for`、`_apply_answer`）**一律用原始结构**，presenter 只作用于响应体。

## 4. 前端改动

### 4.1 `src/lib/types.ts`

`ScaleQuestion` 增加 `measure?`、`unit_hint?`、`banded_input?`、`fallback_options?`、`record_only?`、`when?`；
`ScaleOption` 增加 `min?`、`max?`、`level?`、`abnormal?`、`severity?`。

### 4.2 `src/components/QuestionCard.tsx`

新增实测分档题渲染路径（优先级高于 `single` 按钮组）：

- **主输入**：数字输入框 + 单位后缀 + 施测提示；
- **计时器**：单位为秒时显示「开始计时／停止计时并记录」，停止后自动把用时填入输入框；
- **实时定档反馈**：按 `option.min/max` 本地预演，显示「将记为：<option.label>」，让评估人员当场核对，而不是提交后才发现落错档；
- **兜底选项**：`fallback_options` 渲染为独立按钮（如「不能完成」），点击后清空数值、以选项值提交；
- 数值与兜底选项**互斥**：填了数值则取消兜底选中，选了兜底则清空数值。

### 4.3 `src/app/elder/scale/[id]/page.tsx`

- `handleNext`：`entry.measured !== undefined` 视为已作答；
- `scoreForQuestion`：实测分档题显示「4.5 秒（<4.82 秒）」这类实测值 + 落档描述，而不是既有的 `4.5s`（会让人误以为得 4.5 分）；
- 朗读文本带上 `unit_hint`，让老人听到「请完成五次起坐，把总秒数告诉我」。

## 5. 契约变更（CA-20261111-01）

`docs/api-contract.md` §4 需补齐（均为非破坏性新增）：

| 项 | 变更 |
| --- | --- |
| `question.unit` / `question.unit_hint` | 新增，由 `measure` 展开 |
| `question.banded_input` | 新增布尔，标注「可填数值自动定档」 |
