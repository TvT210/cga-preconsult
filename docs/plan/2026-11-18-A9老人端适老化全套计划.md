## 2. 设计决策

### 2.1 字号与主题都走「作用域 + CSS 变量」，不动组件源码

沿用仓库里已验证过的做法（`.theme-clinical` 那套）：**组件只写语义类名，颜色与字号在作用域里重映射**。

```css
.elder-theme { --e-fs-base: 18px; --e-primary: #0f766e; … }
.elder-theme[data-elder-scale="large"]  { --e-fs-base: 22px; … }
.elder-theme[data-elder-scale="xlarge"] { --e-fs-base: 26px; … }
.elder-theme .text-elder { font-size: var(--e-fs-base); line-height: var(--e-lh-base); }
```

理由：

1. **两端共用组件**（`BigButton` / `AppShell` / `QuestionCard` / `VoiceBar`）不能为老人端改死样式，否则医护端跟着变；
2. 字号三档只需切一个 `data-` 属性，无需在每个组件里透传 `scale` 参数；
3. 默认档（标准 18px）取值与现状完全一致，**不切档时不会因为这次改造改变排版**。

### 2.2 主色与对比度

| 用途 | 取值 | 对白底对比度 | 判定 |
| --- | --- | --- | --- |
| 主色（青） | `#0f766e` | 5.47:1 | AA 正文通过 |
| 主色深（悬停） | `#115e59` | 7.58:1 | AAA 通过 |
| 主色浅底 | `#f0fdfa` | 深字 11.54:1 | AAA 通过 |
| 强调（暖橙） | `#c2410c` | 5.18:1 | AA 正文通过 |

选 `#c2410c`（orange-700）而不是更暖的 `#ea580c`（orange-600，3.56:1）：后者配白字只有 3.56:1，**过不了 AA**，暖橙只能当装饰不能当按钮。对比度由 `tools/check_elder_contrast.py` 实测，数值写进完成记录。

暖橙只用于**「呼叫工作人员」与提醒类按钮**，主行动按钮仍是青色——橙色在大面积使用时会把「警示」语义用滥。

### 2.3 语音条常驻

- `VoiceBar` 改为量表页**吸底常驻**（`sticky bottom-0`），滚动时始终可点「再读一遍」；
- 新增**人声选择**：`speechSynthesis.getVoices()` 过滤 `zh`，把可选人声列成大按钮；浏览器只给 1 个中文音色时隐藏该项并说明；
- 语速沿用 0.6~1.2、0.1 步进（既有实现，不改口径）；
- 「呼叫工作人员」不是摆设：点下去**落一条协助请求**（见下），老人端能看到状态从「已通知」变「已处理」。

### 2.4 一键呼叫的落点：协助请求，不是新提醒

不复用 `alerts`：就医提醒是**医学结论**的产物，混进「老人不会填第 3 题」会污染提醒统计与误报率口径。

新增 `assistance_requests` 表 + 三段接口（老人创建/查看、医护查看/处理）。医护端在患者列表页
置顶一块「待处理协助请求」，处理写 `handler` 与 `handled_at`，**不做自动派单**（无排班数据，编不出来）。

### 2.5 代答入口独立成页

`/elder/proxy`：选量表 → 填代答人姓名与关系 → 直接建/改会话主答人 → 跳转量表页。
复用 A-5 已有能力（`POST /assessments` 带 `proxy_name`、`PATCH /assessments/{id}/responder`），
**不新增后端接口**。量表页仍是唯一填写入口，避免两套填写逻辑。

### 2.6 一步一屏

量表页同屏内容从「语音条 + 题目 + 代答设置 + 4 个按钮 + 说明」压到「语音条 + 题目 + 上一题/下一题」，
代答设置、跳过、暂停收进「其他操作」折叠区。**不隐藏功能，只降默认密度**。

### 2.7 打印大字版

`@media print` 只作用于 `.elder-theme`：隐藏导航/吸底条/按钮，正文强制 20px、纯黑字、去阴影、
每题 `break-inside: avoid`。报告页加「打印大字版」按钮调 `window.print()`。
打印样式不引入新数据，**只改变呈现**。

## 3. 接口（契约 CA-20261118-04）

| 方法 | 路径 | 角色 | 说明 |
| --- | --- | --- | --- |
| POST | `/elder/assistance` | 登录用户（老人限本人） | 建协助请求 `{session_id?, question_code?, note?}` |
| GET | `/elder/assistance?status=` | 登录用户（老人限本人） | 自己的请求，倒序 |
| GET | `/assistance?status=pending` | staff+ | 待处理列表，带患者姓名 |
| POST | `/assistance/{id}/handle` | staff+ | `{action: handle}`，写处理人与时间 |
| GET | `/elder/support` | 登录用户 | `{phone, hours, note}`，取自配置；未配置时 phone 为空串 |

`phone` 未配置时**返回空串**，前端显示「请找身边的工作人员」而不是编一个号码。

## 4. 验收

| 项 | 判据 |
| --- | --- |
| 字号三档 | 三档切换后正文分别为 18 / 22 / 26px；刷新后保持；医护端字号不受影响 |
| 对比度 | 主色/强调与白底、白字与色底均 ≥ 4.5:1，脚本实测 |
| 一步一屏 | 默认屏内只有 1 道题 + 2 个主操作；360px 无横向滚动 |
| 语音条 | 吸底可见；可重复播放；语速可调；≥2 个中文音色时可选；无音色时给出说明 |
| 呼叫 | 点一次落一条 pending；老人端状态可查；医护端处理后变 handled |
| 打印 | 打印预览无导航/无按钮、正文大字、黑白可读 |
| 代答入口 | 从 `/elder/proxy` 进入后会话 `responder=proxy`，量表页顶部有代答横幅 |
| 测试 | 后端 pytest 全绿（新增 ≥8 条）；前端 vitest 全绿（新增 ≥10 条） |

## 5. 老人端视觉基线的处理

`tools/verify_elder_unchanged.py` 的语义改为「**同一基线内**，线 B 的改动不得串色到老人端」。
A-9 合入后需按新视觉重取基线（脚本本身不改判据）。计划文档与 `docs/frontend/医护端视觉规范.md`
的检查项同步改口径：**老人端视觉不再承诺「对二期基线零变化」，只承诺「对 A-9 基线零变化」**。

## 6. 不做的事（本轮明确不碰）

- 方言语音识别 / 语音合成（P4 5.1，需外部服务）；
- 老人端 3D 知识图谱（`docs/plan` 遗留待拍板事项 5，默认不提供）；
- 代答权限校验（谁有资格代答）——需要监护人关系数据，当前库里没有；
- 字号的**服务端**保存（跟随账号跨设备）：本轮只落本地，跨设备属账号偏好，待 B 线偏好接口。
