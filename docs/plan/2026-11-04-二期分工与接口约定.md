## 1. 两条业务线

### 线 A｜采集与判读（Assessment & Collection）
**一句话职责**：把数据**采准**，把判读**做对**。

覆盖模块：预问诊 → 21 张量表采集 → 自动计分判读 → 分支跳转 → AI 对话采集与结构化抽取 → 老人端界面。

交付物：一份**可信的结构化评估证据**（每道题的作答、分值、等级、阳性标记及其症状编码）。

### 线 B｜结论与运营（Insight & Operation）
**一句话职责**：把结论**用好**，把提醒**闭环**。

覆盖模块：疾病库与鉴别权重 → 症状—疾病匹配引擎 → 阈值与权重审批 → 综合评估报告与版式 → 就医提醒与随访 → 质控看板 → 医护端界面。

交付物：一份**可解释、可追溯、可落地执行**的报告与提醒体系。

### 为什么这样切
- 两条线都能独立演示：线 A 演示「采集—判读」，线 B 演示「匹配—报告—提醒」；
- 交汇点只有 **1 个**（下节），耦合度最低；
- 老人端与医护端天然分属两侧，前端不打架；
- 对方同学两边都能上手，后续若进度不均衡可按 §6 的互换项调整。

### 人力对应（2026-11-04 确认）
| 线 | 负责人 | 备注 |
| --- | --- | --- |
| **线 A｜采集与判读** | 同学 | 题库补录是 A 的硬前置 |
| **线 B｜结论与运营** | 本人（提问者） | 资料收集由本人牵头，见 `docs/plan/2026-11-04-线B资料收集清单.md` |

## 2. 唯一的交汇点：标准评估证据（Assessment Evidence）

**A → B 的唯一交付物**（B 的匹配引擎与报告引擎只允许通过 API / 服务层读取，**不得直接查 A 的表**）：

| 字段 | 来源 | 消费方 |
| --- | --- | --- |
| `assessment_scores.total` / `level` / `abnormal` / `severity` | A 的计分引擎 | B 的报告「量表结果」「阳性清单」 |
| `assessment_scores.flags[].symptom_codes` | A 的题库 `flags` 配置 | B 的匹配引擎召回与加权 |
| `assessment_scores.rule_refs` | A 的计分引擎 | B 的报告「结论可回溯」展示 |
| `assessment_scores.needs_manual_review` | A | B 的报告「待人工确认」标记 |
| `GET /assessments/{id}` 的 `score` 对象 | A 的接口 | B 的前端调用 |

**B → A 的唯一交付物**：

| 交付物 | 说明 |
| --- | --- |
| `GET /scales/{code}` 的 `scoring` 规则块 | A 的计分引擎据此执行；B 改规则 → 走契约变更 |
| 症状词表 `docs/structured/disease-library/symptoms.json` | 词条本体归 B（医学口径）；**口语同义词归 A**（抽取侧话术适配） |
| 匹配引擎的 `evidence_insufficient` / 降级结论 | 反馈给 A 的界面表达（提醒为何被降级） |

> **红线**：A 不得改动匹配逻辑，B 不得改动计分规则。任何越界修改在 code review 阶段直接打回。

## 5. 协作机制

### 5.1 契约变更
- 契约由 **B 维护**（B 线改动面更大），A 需要新增字段/接口时提「变更申请」（模板见 `docs/api-contract.md` §0.3）。
- **契约冻结评审**：D0-7 当天完成一次，之后每个 Sprint 第一天复核一次。
- 冻结期内任何**破坏性**改动一律不做，只做新增。

### 5.2 日常节奏
| 频率 | 事项 | 产出 |
| --- | --- | --- |
| 每日 15 分钟 | 站会：昨天完成 / 今天计划 / 阻塞点 | 口头 + 任务板 |
| 每日提交 | 提交信息带线别前缀：`feat(A-xxx): …` / `feat(B-xxx): …` | Git 历史可读 |
| 每周一次 | 契约复核 + 进度对表 + 风险更新 | `docs/plan/契约评审记录.md` 追加 |
| 里程碑 | 交叉 code review（各审对方的 PR） | PR 通过才合 dev |
| Sprint 末 | 联调演示：各自演示本线闭环 | 双方在场 |

> **分支命名**：按 `AGENT.md` 规范，`feat/A-<模块>-<简述>`、`feat/B-<模块>-<简述>`，从 `dev` 切出，完成后合回 `dev` 并删除。
> **提交信息**：`feat(A-scale): 补录 B.16 Braden 量表条目`、`fix(B-match): 修正鉴别扣分封顶逻辑`。

### 5.3 契约一致性校验（放进 CI）
比对 `docs/api-contract.md` 里声明的接口与 `app.openapi()` 的实际路径，缺一即失败——防止两人各写各的、文档漂移。

### 5.4 决策记录
两人无法当场拍板的技术选择（阈值口径、概率口径、字段命名等），写进 `docs/plan/决策记录.md`，格式：`D-YYYYMMDD-NN｜问题｜选项｜结论｜影响面｜日期`。
