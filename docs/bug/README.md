# 缺陷记录（docs/bug）

本目录存放**缺陷（BUG）记录**：问题现象、复现步骤、期望与实际结果、根因与修复方案、验证结论。缺陷判定同样以根 `AGENT.md` 的**领域红线**为最高判据（量表与标准不一致、AI 输出诊断结论、术语违规、结论不可回溯等一律按高优先级处理）。

## 1. 编号规则

```
bug-YYYYMMDD-NNN
```

- `YYYYMMDD`：缺陷登记日期（8 位数字）。
- `NNN`：同日序号，从 `001` 起递增，不足三位补零。
- 示例：`bug-20261104-001`。

每条记录一个独立文件：`docs/bug/bug-YYYYMMDD-NNN.md`，文件名即编号。

## 2. 严重程度

| 级别 | 含义 | 处理要求 |
| --- | --- | --- |
| P0 | 阻断性：服务不可用、数据越权或泄露、AI 输出诊断结论等红线问题 | 立即修复，修复前不得上线 |
| P1 | 严重：主流程不可用、计分或匹配结果错误 | 当日修复 |
| P2 | 一般：局部功能异常、有可接受的绕行方式 | 排入近期迭代 |
| P3 | 轻微：文案、样式、体验问题 | 择机优化 |

## 4. 示例条目

```markdown
# bug-20261104-001 量表缺项时仍输出正式判读等级

| 字段 | 内容 |
| --- | --- |
| 编号 | bug-20261104-001 |
| 日期 | 2026-11-04 |
| 严重程度 | P1 |
| 涉及模块 | backend/app/services/scoring.py、backend/app/api/assessments.py |
| 复现环境 | Windows 11 + Python 3.12 + SQLite；后端 http://127.0.0.1:8000 |
| 负责人 | backend-scale |
| 状态 | 已修复 |

## 复现步骤

1. 以 `nurse/nurse12345` 登录，创建 B.1（基本日常生活活动能力）评估会话。
2. 仅作答 8 项后调用 `POST /api/v1/assessments/{id}/finish`。
3. 查看返回的 `scores[].interpretation` 与 `needs_manual_review` 字段。

## 期望结果

缺项被标记为「待人工确认」，`needs_manual_review` 为真，不输出正式判读等级；已作答条目仍可查看分值与依据。

## 实际结果

接口直接返回「轻度依赖」等级，且 `needs_manual_review` 为 `false`，缺项被按 0 分计入总分。

## 根因分析

`backend/app/services/scoring.py` 的求分阶段未区分「未作答」与「作答为 0 分」，缺项落入默认分支按 0 分累加；判级阶段也未读取缺项标记。

## 修复方案

- 作答表增加「缺项」状态，与 0 分区分；
- 求分阶段统计缺项数量，缺项大于 0 时不执行判级，输出「待人工确认」并置 `needs_manual_review=true`；
- 补充单元测试：全作答、部分缺项、全部缺项三种场景。

## 验证结论

- 验证方式：`python -m pytest tests -q` 全绿，并手工重跑上述三步。
- 回归范围：计分与判读、报告生成、疾病匹配三条链路。
- 关联审查记录：review-20261104-001

## 备注

仅修正引擎逻辑，未涉及题库条目、阈值与提示词版本，题库条目仍为 `draft_pending_medical_review` 待评审状态。
```
