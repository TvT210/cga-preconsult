## 1. 为什么现在的风格要推翻

现状（`frontend/tailwind.config.ts` + `globals.css`）：

- 大面积医疗蓝 `#1d4ed8` 作为按钮与强调色，页面被色块切割；
- 卡片 `rounded-1rem` + 双层阴影 `shadow-card`，内容浮在卡片上，层级噪音大；
- 每个信息点都包一层 `.card .card-pad`，一屏能看的信息很少；
- 进场动画 `fade-in-up` 叠加，正文用 18px 起的适老化字号——**这是老人端的需求，用在医护端就导致信息密度极低**。

结论：**老人端与医护端应该有两套视觉**，不是一套打补丁。
老人端（大字号、高对比、暖蓝、点击目标大）属线 A，不动；
医护端（信息密度高、克制、近黑+teal、无阴影）属线 B，本次重做。

## 9. 踩坑记录（改造过程中实测踩到，勿重蹈）

### 9.1 `tailwind-merge` 会吃掉自定义字号与文字颜色

Tailwind 的 `text-` 前缀同时覆盖「字号」和「文字颜色」。`tailwind-merge` 只认识内置字号刻度，
把自定义的 `text-clin-xs` / `text-clin-sm` 判成**文字颜色**类，于是：

- `cn("text-clin-sm", "text-clin-fg-muted")` → 字号被当成颜色冲突掉，字号回退到继承值；
- `cn("text-white", "text-clin-xs")` → `text-white` 被吞，白字退回继承色，
  叠在近黑主按钮上就变成**「按钮文字消失」**。

修法：`src/lib/utils.ts` 用 `extendTailwindMerge` 把 `clin-*` / `elder-*` 显式登记进 `font-size` 组。

### 9.2 图谱库换型：从 react-force-graph 换到 cytoscape.js

**换型原因**（2026-11-05 实测，见 `docs/research/2026-11-04-知识库可视化开源方案选型.md` 复盘）：

1. **画面会被程序擅自改动**。react-force-graph 的力导向引擎在冷却结束时触发
   `onEngineStop`，若此时再调 `zoomToFit`，视图会突然变形。实测时间线：
   `t≈5s` 自然尺寸 615×552 → `t≈8s` 突变为 384×357（用户反馈「几秒后自动变形」）。
2. **节点不可拖拽**，用户无法手动整理，节点位置每次布局都被重排。
3. **无法切换布局**，只有一种力导向形态。
4. `d3Force` / `zoomToFit` 是**实例方法**（react-kapsule 的 `methodNames`），
   写成 React prop 会被 kapsule 从属性透传中**直接忽略且不报错**——排版参数
   曾经完全没有生效过。

**cytoscape.js 的优势**：布局「一次执行、跑完即静止」；节点默认可拖拽且
**位置保留**；五种布局随用随换；平移/缩放/框选/点选全内建；零运行时依赖、
Canvas 渲染不依赖 WebGL、自带 TypeScript 类型。

**换型后实测结论**：

| 验证项 | 结果 |
| --- | --- |
| 25 秒内画面稳定性 | 包围盒 621×492、像素数 4453 **全程不变** |
| 节点拖拽 | 原位 96 像素 → 0、目标位 0 → 61，**拖动成功** |
| 拖拽后 6 秒 | 位置**保留**，不会被自动重置 |
| 五种布局切换 | 同心圆/环形/网格/树形/力导向全部渲染正常、无报错 |
| 点击节点 | 右栏详情联动正常 |

### 9.3 cytoscape 的画布容器必须是 React 不碰的空 div

cytoscape 会把自己的多层 canvas **注入**容器 div；如果 React 也在同一个 div
里渲染子节点（加载遮罩、悬停提示），React 的子节点协调会把这些 canvas 当成
自己的旧节点去删，抛 `NotFoundError: Failed to execute 'removeChild' on 'Node'`，
**画布被整个摘掉、页面变空白**（本项目实际踩到过，表现为切布局后一片空白）。

规矩：容器 div 只放 canvas，**不放任何 React 子节点**；遮罩与提示框一律作为
**兄弟节点**放在外层 `position: relative` 容器里。

另外：把解析出的颜色放进 `useState` 会让「创建实例」的 effect 反复重建实例
（每次都是新对象 → 引用变化 → 依赖变化），必须用 `useRef` 缓存。

### 9.4 canvas 2D 不认 CSS 变量

`ctx.fillStyle = "var(--c-rose)"` 是无效值，颜色会变黑。必须在运行时用
`getComputedStyle` 把 `--c-*` 解析成真实颜色再传入（见 `graphTokens.tsx` 的
`resolveCanvasColors`）。

### 9.5 截图脚本必须按角色登录

`RoleGuard` 会把越权访问重定向到本端首页。用护士令牌访问 `/elder` 会被弹回 `/staff`，
截图「看起来正常」实则拍错了页面——老人端零变化曾因此**假通过**。
`tools/capture_staff_ui.py` 现按 `staff` / `elder` 分别登录，并校验最终 `location.href`。

### 9.6 3D 图谱（react-force-graph-3d + three.js）的四个坑

3D 视图实测踩到、且**报错信息完全指不到根因**的坑，逐条记录：

1. **画布尺寸默认是整个视口**。`three-render-objects` 的 `width/height` 默认值是
   `window.innerWidth/innerHeight`，不显式传就会按 1600×1100 建画布、把容器撑破，
   投影坐标也跟着算错。必须用 `ResizeObserver` 量容器后显式传 `width` / `height`。
2. **访问器写成内联箭头函数 → 连线全部消失**。库靠「属性是否变化」决定要不要重建
   场景对象，而连线几何体的顶点**只在布局 tick 时填充**（引擎停止后不再更新）。
   `nodeThreeObject={(n) => ...}` 每次渲染身份都变 → 库反复重建场景对象 →
   引擎已停时新建的连线几何体永远是空的。**必须 `useCallback` 固定引用**。
3. **d3-force 会把 `link.source` / `link.target` 从字符串换成节点对象**。
   之后拿它们去查 id 集合必然落空 → 所有连线被判「端点不可见」而全部隐藏。
   额外存一份 `sourceId` / `targetId` 字符串备用。
4. **孤立节点（度为 0）会被斥力推到极远处**。本项目 45 个「尚未挂到任何病种」的词条
   没有连线、只受斥力作用，把图谱半径从 ~139 撑到 1215，主体簇被挤成一小团。
   处理：孤立词条**默认不参与 3D 布局**，由页面上的「无关联词条（45）」开关按需打开
   （数量公开，不静默隐藏）。

另外两点经验：

- **取景用「距离 80 分位数」而不是包围盒半径**：包围盒会被离群点撑大，相机一退就退到极远。
- **取景只做一次**，且必须等「引擎停稳 + 节点对象就绪」后再做（`onEngineStop` 触发时
  three 对象可能还没建好，此时算中心会得到空值）。之后视角完全交给用户。
- 3D 依赖必须客户端加载（WebGL 上下文在服务端不存在），用
  `next/dynamic(..., { ssr: false })`。
- headless 截图需 `--enable-unsafe-swiftshader --use-angle=swiftshader`，
  **不能加 `--disable-gpu`**，否则没有 WebGL。
