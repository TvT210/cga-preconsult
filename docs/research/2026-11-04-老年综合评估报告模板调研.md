# 老年综合评估报告模板 · 公开资料调研报告

- **调研日期**：2026-11-04
- **调研目的**：为「老年人就医前预问诊与老年综合评估系统」的**综合评估报告模板**（封面 / 目录 / 分区表格 / 页眉页脚 / 签署栏）提供公开资料依据
- **项目对应文档**：`docs/项目构想总需求.md` §1.1（建设依据）、§5.9（报告生成）
- **调研性质**：只读网络调研；**未修改任何项目代码或非本文件的其他文件**

---

## 0. 结论先行

1. **项目文档中的「标准第 9 章规定报告要求」需要更正**：WS/T 888—2026 的**第 9 章是「评估实施」**（9.1 评估目标与侧重、9.2 评估结果及干预）；**报告内容与格式的强制要求在第 10 章「质量控制」的 10.3「总结报告」**，归档要求在 10.4「数据管理」[S1-p3]。本项目的模板设计必须同时覆盖 9.2 与 10.3/10.4。[S1-p3]
2. **标准对报告的强制要求其实很「薄」**，只有两句：10.3.1「报告内容应包括**评估量表名称及评估结果、干预计划**」、10.3.2「报告内容应完整准确，**格式规范**」；9.2.1「评估人员应依据筛查及评估结果**出具评估报告**」；10.4.2 报告**宜纳入病案**或纳入个人健康管理档案。[S1-p3]
3. **封面、目录、页眉页脚、签署栏在 WS/T 888 中均未被规定**——属于「推荐项 / 行业惯例」，其可追溯的国内依据来自 GB/T 42195—2022 附录 C（签署与评估地点栏）[S9]、MZ/T 039—2013 配套报告表（评估员签名×2、信息提供者签名、机构专家组会签、主管部门审核盖章）[S10]、以及《国家基本公共卫生服务规范（第三版）》居民健康档案表单目录（封面 / 个人基本信息表 / 健康体检表 / 重点人群管理记录表 / 填表基本要求）[S11]。
4. **最佳可照抄的国内模板骨架**是 GB/T 42195—2022 附录 C《老年人能力评估报告》[S9] 与 WS/T 888 附录 A.1（基本情况）[S1-p2]，二者组合可直接支撑「基本信息 → 量表结果 → 等级/结论 → 干预计划 → 签署」的主干。
5. **本报告第 6 节给出可直接实现的 `report_templates` 内容 JSON 草案**（约 12 个顶层字段、9 个报告分区、约 30 个区块类型定义），字段命名已对齐本仓库 `docs/sql/schema.sql` 的 `scale_templates` / `cga_reports` 既有风格。
6. **待确认项较多**：interRAI / RAI / EACS 官方原文**未获取到**（见 §7），须由医学专家或病案科补齐确认。

- 第 13–15 栏对应 **9.2.2 / 9.2.3 / 10.3.1** [S1-p3]。
- 第 17–18 栏对应 **9.2.1（出具报告）、10.4（数据管理）** 与 **电子病历应用管理规范的归档/留痕规则** [S1-p3][S12]。

## 4. 专业版 / 通俗版 / 存档版三种版式的差异建议

| 维度 | 专业版（临床医生） | 通俗版（老人 / 家属） | 存档版（病案归档） |
| --- | --- | --- | --- |
| **主要读者** | 老年医学科/全科医师、专科医师、MDT 成员 | 老年人本人、家属、照护者 | 病案科、质控、等级评审、医保/科研 |
| **首要目的** | 支持临床决策与 MDT 讨论 | 让老人和家属**看懂并能行动** | 满足病历完整性、可追溯、不可篡改 |
| **内容取舍** | 保留全部 21 量表分项分、条款依据、判读阈值、疾病匹配依据链 | 只保留「结论 + 与我相关的事 + 我该做什么」 | 保留全量原始数据 + 工具版本 + 签署链 + 审计轨迹 |
| **术语** | 保留专业术语与阈值（如 MNA-SF ≤9 分提示营养不良风险） | 全部转译为生活语言（「吃得太少，肌肉在减少」），并括注原分值 | 保留原始术语与编码（ICD-10 等） |
| **风险等级** | 分级 + 判读依据 | 只呈现「红/黄/绿」三色 + 一句话说明「这意味着什么」 | 分级 + 依据 + 阈值版本 |
| **AI 与疾病匹配** | 展示依据链（命中/缺失症状、鉴别排除理由） | 只呈现「建议看哪个科 + 为什么现在要去」，**必须显著标注「仅供参考，不是诊断」** | 完整输入/输出/阈值/最终人工判断记录 |
| **版式** | 双栏或单栏表格为主；字号 10.5–12 pt；可嵌图表 | **单栏、大字号**；正文 ≥18 pt；行距 ≥1.3 倍；段间距 ≥ 行距×1.3；无衬线字体；文本对比度 ≥4.5:1；关键结论用色块/图标而非仅靠颜色 | 与专业版一致，另加封面页、目录、页眉页脚、签署区、归档元数据页 |
| **目录** | 有（分区级） | 无（或仅 3–5 条「你关心的几件事」） | 有（分区级 + 附录级） |
| **页眉/页脚** | 页眉：机构 + 报告标题 + 报告编号；页脚：页码「第 X 页 共 Y 页」+ 密级 + 版本 | 页眉仅机构与标题；页脚含「看不懂请找医生」提示与联系电话 | 页眉：机构 + 报告编号 + 版本 + 密级；页脚：页码 + 报告编号 + 版本 + 归档标识 |
| **签署区** | 评估者 + 复核者签名 + 日期 | **无签名**（或仅「您已了解」确认勾选，不作医疗文书） | 评估者 ×2 + 信息提供者 + 复核者 + MDT 负责人 + 机构盖章 + 主管部门审核（按 S10 的链） |
| **导出格式** | PDF（可打印归档）+ 屏幕版 | PDF/图片（大字版），**建议 A4 纵向、每页 ≤3 个要点块** | PDF/A 或打印装订件 + 结构化 XML/JSON + 哈希值 |
| **关键约束来源** | S1-p3（10.3.1/10.3.2）、S9 | S13（字号/行距/对比度/语音）、B1（免责声明） | S12（归档、留痕、修改审批、保存期限）、S1-p3（10.4.2/10.4.3）、S10（盖章链） |

**版本管理建议（建议项，非标准强制）**
- 三种版式共享**同一份评估数据与同一套结论对象**，仅**呈现层（render profile）**不同；避免三份内容互相漂移。
- 通俗版**不得新增或删改结论**，只做表述转换；任何转换需保留 `source_ref`（指向专业版区块 ID）以备质控回溯。

## 5. 版式与结构规范

### 5.1 封面要素（建议项；依据见 §2 编号 8/21）

| 元素 | 必填 | 说明 | 来源 |
| --- | --- | --- | --- |
| 报告标题 | 是 | 「老年综合评估报告」（专业版 / 通俗版 / 存档版 副标题标注） | S1（标准术语「老年综合评估」） |
| 机构名称 + 科室 | 是 | 医疗机构全称 + 执行科室（老年医学科 / 全科 / 社区卫生服务中心） | S1-p1（5.1 评估人员属机构内） |
| 评估对象标识 | 是 | 姓名、性别、年龄；**档案版可用住院号/门诊号替代姓名** | S9（A.2） |
| **报告编号** | 是 | 建议格式 `机构码-科室码-YYYYMMDD-流水号`，须全局唯一、可反查 `cga_reports.id` | S9（A.1「评估编号」） |
| **版本号** | 是 | 报告内容版本（semver），与模板版本、量表版本分别记录 | S12（追溯能力）、S1-p3（10.4.1） |
| 评估基准日期 | 是 | YYYY-MM-DD；专业版精确到时分 | S9（A.1.2） |
| 评估原因 | 是 | 首次 / 常规 / 即时 / 复评 / 其他 | S9（A.1.3） |
| 密级/用途标识 | 是 | 三选一：专业版 / 通俗版 / 存档版；存档版加「病案归档」字样 | 惯例 |
| 编制人 / 审核人 | 是 | 姓名 + 职称 | S9（附录 C 签名）、D1 |
| 生成时间与系统标识 | 建议 | 含量表版本集、规则版本、模型与提示词版本 | S1-p3（10.4.1 全流程管理）、项目 §5.11 留痕 |

### 5.2 目录（建议项）
- 层级：分区级（一级）→ 区块级（二级），不深入到量表分项。
- 目录条目由模板 `sections[].title` 自动生成，页码在渲染时回填。
- 存档版目录须与正文分区**完全一致**（便于病案科按目录核对完整性）。

### 5.3 页眉页脚（建议项）
- **页眉**：左 = 机构名称 + 科室；中 = 报告标题；右 = 报告编号 + 版本号。字号建议 9 pt，档案版 9–10.5 pt。
- **页脚**：左 = 密级/用途标识 + 「不构成诊断」提示（通俗版措辞更直白）；中 = 页码「第 X 页 / 共 Y 页」；右 = 归档标识（存档版：「已归档 · 归档时间 YYYY-MM-DD · 归档号」）。
- 页码与页眉页脚**不得**因分节而重置（除封面与目录使用罗马数字外）。

### 5.4 签署区（建议项 + 参考 S9/S10）
建议四个层级，均含「签名 + 日期」：

| 层级 | 角色 | 依据 |
| --- | --- | --- |
| 1 | 评估者（主评估医师 / 护士 / 技师，含资质） | S1-p1（5.1 评估人员须培训考核合格）、S9（附录 C 评估人员签名）、S10 |
| 2 | 信息提供者 / 家属 / 照护者 | S9（附录 C 信息提供者签名）、S10 |
| 3 | 复核者（具备资质的上级医师） | S12（第十六条 上级医务人员审阅、修改、确认） |
| 4 | MDT 负责人 / 机构（存档版：专家组会签 + 主管部门审核盖章） | S1-p3（10.1、9.2.2）、S10 |

- 通俗版**不设**医疗签名栏；可设「家属已阅读」勾选与日期（明确标注「非医疗文书」）。
- 签署区须出现在**每一条款要求的末尾**（对齐 S9 附录 C 的位置：正文结论之后）。

### 5.5 存档要求（版本锁定 / 脱敏）

| 要求 | 依据 | 落地建议 |
| --- | --- | --- |
| 报告设置**归档状态**；归档后**原则上不得修改** | S12 第十七条（强制） | `cga_reports.locked` 置 true + 状态机 `draft → reviewed → locked → archived` |
| 确需修改须**经医疗机构医务部门批准**并**保留修改痕迹** | S12 第十七条（强制） | 新建版本记录 + `template_approvals` 审批 + `audit_logs` 留痕 |
| 系统须具备**创建、修改、归档的追溯能力**；保存历次操作印痕、时间与人员 | S12 第六条/第十四条/第十五条（强制） | 审计表记录操作人、时间、前后值 |
| 报告**宜纳入病案**或纳入个人健康管理档案 | S1-p3 10.4.2（推荐） | 提供「推送到病案/健康档案」接口或归档包 |
| 记录归档、保存与使用按《医疗机构病历管理规定》《电子病历应用管理规范（试行）》执行 | S1-p3 10.4.3（强制引用） | 存档版输出遵循病历格式要求 |
| 评估信息**完整性、安全性、保密性** | S1-p3 10.4.1、S1-p1 4.4（强制） | 权限控制 + 导出脱敏 + 访问审计 |
| 保存期限 | S12 第十九条（门急诊电子病历 ≥15 年） | 由病案科按本地规定确认具体年限 |
| **脱敏**：科研/教学导出 | 项目 §5.11（最小必要、科研导出需脱敏） | 姓名/身份证/住址/电话替换为代号；保留报告编号与量表分值 |

CREATE TABLE report_templates (
  id SERIAL NOT NULL,
