# 知识库可视化开源方案选型（医护端「疾病—症状—量表」关系图谱）

> 调研日期：2026-11-04
> 调研范围：GitHub 开源、可商用的 React 关系图谱 / 网络图 / 矩阵热力图组件与模板
> 目标项目：`frontend/`（Next.js 15.5.29 App Router + React 19 + TypeScript 5.7 + Tailwind 3.4）
> 数据来源：本文所有 star 数、许可证、最近更新时间均取自 GitHub REST API（`api.github.com/repos/*`）与 npm registry 实测，**未凭记忆填写**；查不到的项在第 6 节明确标注「未获取」。

## 1. 结论先行

**主选：`react-force-graph-2d`（`vasturiano/react-force-graph`，MIT）**
理由：Canvas 2D 渲染不依赖 WebGL（医护端老旧机器 / 内网无 GPU 环境可正常降级），MIT 协议无传染性、npm 直接安装即用于 Next.js 15 `'use client'` 组件，且其 `graphData` 契约与本项目后端**已经存在的** `GET /knowledge/graph` 接口返回的 `{nodes, edges}` 结构几乎一一对应（仅需 `edges` → `links` 改名），改造量最小。

**备选：`@xyflow/react`（`xyflow/xyflow`，MIT）**
理由：若后续要从「力导向散点图」升级为「可拖拽编排的关系看板 / 层级树 / 预问诊流程图」，React Flow 的节点编辑器模型、缩放控件、内置 minimap 与官方示例集合更成熟，MIT 协议同样干净；代价是 160 节点需要额外做布局计算（dagre/ELK），且缺少现成的力导向布局。

**矩阵视图（症状 × 疾病）另选：`@nivo/heatmap`（`plouc/nivo`，MIT）** —— peerDependencies 显式声明支持 `react ^19.0.0`，且 `@nivo/matrix` 在 npm 上并不存在（已核实为 404），热力图是 nivo 官方对应能力。

## 3. 主选方案详细接入方案（react-force-graph-2d）

### 3.1 安装

```bash
cd frontend
npm install react-force-graph-2d
```

无额外构建工具要求；不需要 `d3-force` 单独安装（已内嵌于 `force-graph`）；不需要额外 CSS 文件（Canvas 渲染）。

### 3.2 数据结构映射（对接后端已有接口）

**关键发现**：本项目后端**已经实现了图谱接口** `GET /knowledge/graph`（`backend/app/api/knowledge.py:52`），返回结构如下：

- 节点：`{ id, type: "disease"|"symptom"|"scale", label, group, risk?, meta: {...} }`
  - `disease` → `group` = 所属系统、`risk` = 风险等级、`meta` = aliases / review_status / atypical / advice
  - `symptom` → `group` = 症状分类、`meta` = synonyms / probe（鉴别追问话术）
  - `scale` → `group` = 量表维度、`meta` = method / item_count
- 边：`{ source, target, kind: "core"|"secondary"|"focus"|"synonym", label, item?, item_text? }`
- 附加：`stats`（nodes/edges 计数、按类型计数、按边类型计数）、`notice`（医学免责提示）

**映射规则（几乎零改造）**：

| 后端字段 | 前端映射 | 说明 |
|---|---|---|
| `nodes[].id` | 节点 `id` | **已天然全局唯一**（`disease:CODE` / `symptom:CODE` / `scale:CODE`），可直接透传，无需重编号 |
| `nodes[].label` | 节点 `label` | 直接使用（疾病名 / 症状词 / 量表名） |
| `nodes[].type` | 节点 `group` | 用于 `nodeAutoColorBy="group"` 自动配色；**建议另存一份 `type` 字段**用于「按类型过滤」 |
| `nodes[].group` | 节点 `val`（节点大小） | 疾病=系统分组、量表=维度，均为枚举；**建议改为度数（degree）派生**，见 3.4 |
| — | 节点 `size` | 后端未提供，需前端按关联边数派生（见 3.4） |
| `edges[]` | `links[]` | **唯一必须的改动：属性名 `edges` → `links`**；`source`/`target` 已与库契约一致 |
| `edges[].kind` | `links[].kind` | 用于连线样式：`core` 实线粗、`secondary` 细、`focus` 虚线、`synonym` 点线 |
| `edges[].label` | `links[].label` | hover 连线时显示（核心症状 / 关注项说明 / 同义词） |
| `edges[].item` + `item_text` | 详情面板字段 | 「某病种关注量表 B.16 第 3 题」 |

**注意**：后端已有 `node_type`（`disease`/`symptom`/`scale`）与 `keyword` 两个查询参数，**前端可直接调用后端做类型过滤与搜索**，无需在前端重新过滤全量图谱——但见 3.6 的取舍说明。

### 3.3 最小可用示例（TypeScript，19 行）

```tsx
'use client';
import { useMemo } from 'react';
import ForceGraph2D from 'react-force-graph-2d';

type GNode = { id: string; label: string; group: string; size: number };

export default function KbGraph({ nodes, edges }: {
  nodes: GNode[]; edges: { source: string; target: string; kind: string }[];
}) {
  const graphData = useMemo(() => ({
    nodes: nodes.map((n) => ({ ...n, val: n.size })),
    links: edges.map((e) => ({ ...e })),
  }), [nodes, edges]);

  return (
    <div className="h-[600px] w-full">
      <ForceGraph2D
        graphData={graphData}
        nodeAutoColorBy="group"
        nodeLabel={(n) => `${n.label}（${n.group}）`}
        nodeRelSize={4}
        linkColor={() => 'rgba(148,163,184,0.45)'}
        onNodeClick={(n) => console.log(n.id)}
        backgroundColor="#ffffff"
      />
    </div>
  );
}
```

**最小示例对应到本项目**：把 `nodes` / `edges` 换成 `GET /knowledge/graph` 的返回值即可（`edges` → `links`）。官方类型定义见 `src/packages/react-force-graph-2d/index.d.ts`（仓库内），完整示例目录见 `example/`（含 `highlight`、`click-to-focus`、`filter` 类交互可抄）。

### 3.4 交互设计要点（对照需求逐条落实）

| 需求 | 实现方式 | 复杂度 |
|---|---|---|
| 按类型过滤（疾病/症状/量表） | 三种实现，建议第 2 种：①前端过滤 `graphData`（快，但整图重排）；②**调用后端 `?node_type=`**（推荐，语义一致，与后端 `stats.by_type` 同步）；③节点淡出（`nodeCanvasObject` 里按类型跳过绘制） | 低 |
| 搜索 | 后端已支持 `?keyword=`（节点 label / id 子串匹配，并同步裁剪关联边）。前端再叠一层「输入即防抖请求」即可 | 极低（后端已完成） |
| 点击节点看详情 | `onNodeClick={(node) => setSelected(node)}` → 右侧详情抽屉。节点原始字段全在 `node` 上（`meta.aliases`、`meta.synonyms`、`meta.probe`、`meta.advice`、`meta.item_count` 均可直接渲染）。疾病→症状的完整清单建议懒加载 `GET /knowledge/symptoms/{code}`（后端已有） | 低 |
| 悬停看关系数 | `onNodeHover` 维护 `hoverId`，再用 `useMemo` 预先算好 `degreeMap: Map<id, 边数>`，hover 时在 `nodeLabel` 或自定义 tooltip 里显示「关联 N 项」 | 低 |
| 症状 → 关联疾病与量表（列表/矩阵视图） | **不要用图谱硬凑**。用后端图数据前端派生「症状 → 疾病列表 / 量表列表」双栏表；或用 `@nivo/heatmap` 做 113×28 的症状×疾病矩阵（单元格值 = `core=2 / secondary=1 / 无=0`），点格子跳转到图谱并高亮该症状 | 中（矩阵需新写约 1 人日） |
| 边类型区分 | `linkColor` / `linkWidth` / `linkDashArray` 按 `kind` 映射（core 实线 2px、secondary 实线 1px、focus 虚线、synonym 点线） | 低 |

### 3.5 性能注意（160 节点 / 约 400 边）

**结论：本数据量下 force-directed 性能完全不是瓶颈。**

- d3-force 的模拟成本随节点数近似 O(n log n)（Barnes-Hut 四叉树），160 节点属于玩具级；`force-graph` 自带 `warmupTicks`（预热 tick）与 `cooldownTicks`（冷却 tick）机制，可在挂载时同步跑完若干 tick 再首帧渲染，避免「先看到散点再看到成图」的抖动。
- Canvas 2D 绘制 160 个圆 + 400 条线，在普通办公机上稳定 60fps。
- **真正需要注意的是中文标签**：节点默认不画文字（只有 hover 才显示 `nodeLabel`），这是好事——113 个症状名全量绘制会导致视觉噪声。若要常显标签，必须：
  - 调大 `nodeRelSize` 与 `linkDistance` 避免重叠；
  - 或只在 `zoom > 2.5` 时绘制文字（`onZoom` 回调切换 `nodeCanvasObject` 内的绘制逻辑）；
  - 或用 `nodeCanvasObject` 自绘时加简易文字避让（按角度优先级跳过重叠标签）。
- 内存/对象稳定性：不要在每次 render 时重建 `graphData` 对象，否则 force 引擎会重置布局并触发重排。必须用 `useMemo` 固定引用（见 3.3 示例）。
- 若未来节点数增长到数千级，再考虑换 cytoscape.js / sigma.js；160 节点远未到需要换的门槛。

### 3.6 SSR / 水合（Next.js 15 + React 19）注意事项

这是本方案**唯一的实质性风险点**，逐条列出：

1. **必须 `'use client'`**。组件内部使用 `window` / `document` / `canvas`，服务端无法渲染。`'use client'` 只把组件标记为客户端组件，**不等于跳过 SSR**——组件在服务端仍会被预渲染一次（输出一个空 canvas 容器）。
2. **不要用 `dynamic(..., { ssr: false })` 强行绕过**：在 Next 15 App Router 中，`ssr: false` 只允许在客户端组件里使用；更稳妥的做法是让组件在服务端正常输出占位容器、在 `useEffect` 后由库自己初始化 canvas。`react-force-graph-2d` 内部已经处理了这个时机。
3. **容器必须有确定尺寸**。库通过 `getBoundingClientRect` 量测父容器；父容器若为 `height: 100%` 且父级链上存在无高度节点，量测结果为 0，表现为「图不显示」。**对策**：外层写死 `h-[600px] w-full`（见 3.3 示例），或用 `ResizeObserver` 自行维护像素宽高传给 `width` / `height` prop。
4. **已知 Next.js 15 问题 [#551]**：在 Next.js 15 项目里给 `<ForceGraph2D ref={...}>` 传 ref 会出现无限重渲染。根因是 `react-kapsule` 的 `useEffect` 依赖数组错误（`react-kapsule` issue #14，已于 2024-11-07 关闭并修复），作者在 issue #551 中于 2024-11-13 确认修复已随 `react-force-graph-3d@1.24.6` 发布。当前 `react-force-graph-2d@1.29.2` 依赖 `react-kapsule@^2.6`，**已包含该修复**。
   - **实操建议**：仍优先避免用 `ref` 做 imperative 调用（`centerAt` / `d3Force`）；若必须用，务必锁定 `react-force-graph-2d` ≥ 1.26，并在开发期观察控制台是否有反复的 render 日志。
   - 备选规避方案：把图谱组件整体用 `next/dynamic` 以 `ssr: false` 懒加载（在一个 `'use client'` 包装组件里），彻底切断服务端预渲染路径。
5. **`graphData` 必须 memo 化**（见 3.5）。这同时也是 [#551] 那类「重复渲染」问题的常见诱因。
6. **不要在 render 阶段读取浏览器状态**（`localStorage`、`window.innerWidth`）来决定节点集合，否则会触发 Next 15 / React 19 的 hydration mismatch。搜索/过滤状态应放在 `useEffect` 或事件回调里更新，或通过 `useState` 的初始值（服务端与客户端一致）传入。
7. **CSS**：本项目 Tailwind 3.4 无需为该库写任何配置；但要确认 `overflow-hidden` 与 `z-index` 不被全局样式裁掉画布。

### 3.7 无障碍与降级

- **Canvas 无障碍**：Canvas 绘制的内容对屏幕阅读器不可见。本项目是医护端桌面/平板场景，建议补齐：
  - 提供一个「列表视图」作为等价替代（无障碍要求 + 也是矩阵视图的复用），让所有节点/关系可被键盘与读屏访问；
  - `nodeLabel` 的文案本身就是悬停信息，但不能替代可聚焦交互；
  - 若需要完全合规，用 `@xyflow/react`（DOM 节点）或 visx（SVG）方案替代 Canvas 渲染。
- **WebGL 不可用的降级**：主选方案 **不使用 WebGL**（Canvas 2D），因此不存在 WebGL 降级问题。若未来改用 sigma.js / G6 WebGL 模式，需准备 Canvas/SVG 回退。
- **JS 异常降级**：用 React ErrorBoundary 包住图谱组件；出错时回退到「列表视图」，保证核心信息（症状→疾病/量表关联）仍可读。
- **打印/导出**：Canvas 内容无法被浏览器打印。若医护需要打印图谱，需额外实现「导出 PNG」（`graphRef.current.canvas()` → `toDataURL`）或提供列表视图打印。

## 4. 备选方案说明

### 4.1 备选 A：`@xyflow/react`（xyflow/xyflow，MIT）

**什么时候该换**：当需求从「浏览关系」升级为「编辑关系」或「表达预问诊流程」时。例如：
- 需要医护手动把某个症状挂到某量表、拖拽调整层级；
- 需要展示「疾病 → 症状 → 追问话术 → 量表题目」的**有向流程**，而非无向关联；
- 需要内置 minimap、缩放控件、框选等编辑器级交互。

**优势**：
- MIT 协议最干净，官方维护活跃（最近更新 2026-11-03，38.9k star）；
- 节点是真实 DOM（`<div>`），**天然无障碍、可用 CSS/Tailwind 定制、可键盘聚焦**，比 Canvas 更好做无障碍合规；
- 官方示例集合庞大（`examples/` 目录），布局/搜索/自定义节点等可直接抄；
- 内置 `<MiniMap>` / `<Controls>` / `<Background>`，医护端上手成本低。

**代价与坑**：
1. **没有力导向布局**。160 节点必须自己算坐标：引入 `dagre`（分层，适合「疾病→症状→量表」三层）或 `elkjs`（更复杂，体积大）。这会是主要工作量来源。
2. **需额外引入 CSS**：`import '@xyflow/react/dist/style.css'`。Tailwind 3.4 项目中若用 preflight，注意其 `button` 等基础样式与 React Flow 的按钮样式冲突（建议用 `@layer components` 覆盖）。
3. **边是有向的**：本项目 `synonym` 关系（症状↔症状）是**对称**的，React Flow 需要两条边或 `type: 'straight'` + 双向处理，是额外细节。
4. **节点组件要自己写**：疾病/症状/量表三种卡片式节点各需一个自定义 `nodeTypes`，含标签截断、中文排版、风险等级徽标。

**最小示例（10 行）**：

```tsx
'use client';
import { ReactFlow, Background, type Node, type Edge } from '@xyflow/react';
import '@xyflow/react/dist/style.css';

export default function KbFlow({ nodes, edges }: { nodes: Node[]; edges: Edge[] }) {
  return (
    <div className="h-[600px] w-full">
      <ReactFlow nodes={nodes} edges={edges} fitView>
        <Background />
      </ReactFlow>
    </div>
  );
}
```

### 4.2 备选 B：`cytoscape.js` + `react-cytoscapejs`（均 MIT）

**什么时候该换**：需要图分析能力（中心度、路径查找、社区发现），或需要极其成熟的样式系统（`style` 数组：颜色、线型、标签、边框一次配齐）。

**优势**：11.2k star、MIT、生态最成熟（布局器、统计算法扩展多）；`cytoscape.js` 本身框架无关，无 React peer 限制。

**代价与坑**：
- `react-cytoscapejs` 官方包**停更于 2021**（npm `2.0.0`），peer 锁 `cytoscape@^3`；建议**只用 `cytoscape.js` 核心库 + 自写 60 行 React 封装**，不要依赖旧 wrapper；
- 核心库无 React 19 约束，但自己封装时需处理 `useEffect` 中初始化 + `useEffect` 清理销毁，避免 React 19 StrictMode 双调用导致重复实例；
- 布局质量默认不错，但中文标签重叠需自己调 `text-margin-y` / `text-max-width`。

### 4.3 明确排除的方案

| 方案 | 排除原因 |

| `antvis/G6` v5 | MIT 但无官方 React 绑定（`@antv/g6-react` npm 404），需自写绑定，体积 7.6 MB，ROI 低 |
