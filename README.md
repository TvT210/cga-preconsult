# 老年人就医预问诊与老年综合评估系统

面向**老年人就医前预问诊**场景的适老化智能平台：**21 张量表规范采集 + 大模型对话补充 + 老年综合评估报告生成 + 易发疾病匹配提醒**，前后端分离架构。

建设依据为 **WS/T 888—2026《医疗机构老年综合评估技术操作标准》**，21 张量表取自其附录 B；题库、阈值、提示词全部入库可配置、可审计。

系统分两端使用：

| 端 | 使用者 | 主要能力 |
| --- | --- | --- |
| **老人／家属端** | 老年人、家属／照护者 | 适老化问卷作答、语音对话、报告查看、就医提醒 |
| **医护端** | 评估人员（护士／技师）、医生、知识库管理员、系统管理员 | 评估任务、现场施测、复核、疾病库与阈值配置、统计质控 |

## 功能模块

| 模块 | 能力要点 |
| --- | --- |
| 预问诊与病史采集 | 身份识别、知情同意留痕、基本信息／主诉现病史／既往用药过敏史／生活方式，字段级增量保存，阳性回答触发智能追问 |
| 21 张量表评估中心 | 依据附录 B 组织为「一般情况—躯体功能—精神心理—社会与环境—老年综合征」；题库分层（量表→分组→题目→选项→分值），支持筛查—评估分支跳转、断点续填、实测项计时录入 |
| 自动计分与判读引擎 | 求和／计数／取最值／分级映射等规则求分后判级；输出分值、等级、阴阳性与标准依据条文号；缺项与超范围标记「待人工确认」，不强行出结论 |
| 适老化交互 | ≥18pt 正文、高对比、大按钮、语音播报、进度提示与随时暂停、家属代答标注并记录代答人、一键呼叫人工协助 |
| AI 对话与老人专属医疗数据库 | 按话题清单引导式对话（文本／语音）→ 结构化抽取 → 写入老人维度专属数据库，形成动态健康画像；对话与量表不一致时标记冲突交医护复核 |
| 定期自动评估 | 定时任务（Celery Beat）按风险等级周期触发，**仅基于已有信息**生成「AI 补充评估」结论与趋势，不替代正式量表施测 |
| 老年易发疾病信息数据库 | 疾病编码与别名、典型症状权重、老年人非典型表现、高危因素、鉴别要点、关联量表项、风险等级、就医建议与来源版本 |
| 多候选匹配与分级提醒 | 症状归一化 → 候选召回 → 加权打分 → 同症多病鉴别 → **Top-3 及以上候选**，输出「匹配度 + 参考概率 + 命中／缺失／排除依据」，按立即就医／尽快就医／择期就诊／居家观察四级提醒 |
| 老年综合评估报告 | 基本信息、量表结果、四维小结、阳性问题清单、AI 补充、疾病匹配、干预建议、多学科意见、随访计划；支持 PDF／Word 导出，归档后锁定版本 |
| 随访与健康管理 | 按风险等级自动生成随访周期与提醒，到期再评估并对比趋势，连续恶化或新增高危项时升级提醒 |
| 权限、安全与审计质控 | 基于角色的访问控制（老人仅可访问本人数据）、知情同意与撤回、敏感字段加密与日志脱敏、全链路版本留痕、审计日志与质控指标看板 |

## 快速开始

**前置条件**：Python 3.12、Node.js 20+、pnpm 9+。本机为 Windows 11 + PowerShell 5.1，**不支持 `&&` 连接符**，请逐条执行命令（可用 `;` 或分步执行）。

### 后端（5 步）

1. 进入后端目录

```powershell
cd D:\ALLCODE\work\word2\backend
```

2. 创建并激活虚拟环境

```powershell
python -m venv .venv
```

```powershell
.\.venv\Scripts\Activate.ps1
```

3. 安装依赖

```powershell
pip install -r requirements.txt
```

4. 启动后端（默认 SQLite，自动建表并播种预置账号与草稿题库）

```powershell
python -m uvicorn app.main:app --reload --port 8000
```

5. 验证健康检查

```powershell
Invoke-RestMethod -Uri 'http://127.0.0.1:8000/api/v1/health'
```

后端地址：`http://127.0.0.1:8000`；OpenAPI 交互文档：`http://127.0.0.1:8000/docs`。

### 前端（4 步）

1. 进入前端目录

```powershell
cd D:\ALLCODE\work\word2\frontend
```

2. 安装依赖

```powershell
pnpm install
```

3. 配置接口地址（用编辑器新建 `frontend/.env.local`，写入一行；不要用 PowerShell 5.1 的 `Set-Content -Encoding UTF8` 写入，避免带入 BOM）

```text
NEXT_PUBLIC_API_BASE=http://127.0.0.1:8000/api/v1
```

4. 启动前端

```powershell
pnpm dev
```

前端地址：`http://127.0.0.1:3000`。

> 环境变量、数据库切换、端口排查等详见 [`deploy/Install.md`](deploy/Install.md)。

## 核心设计说明

| 设计点 | 说明 |
| --- | --- |
| **配置化而非硬编码** | 题库、计分规则、判读阈值、匹配权重、就医提醒阈值、提示词模板全部入库，带版本并可审批变更；业务代码不写死医学规则与阈值 |
| **判读可回溯** | 每条判读结论都能回溯到具体题目作答与命中的规则条目（含标准依据条文号），缺项与冲突标记「待人工确认」而非强行出结论 |
| **匹配输出三件套** | 疾病匹配结果同时给出**匹配度**（0~100，可解释）、**参考概率**（归一化相对可能性）与**依据**（命中症状／缺失关键症状／被鉴别排除的理由），至少返回 Top-3 候选 |
| **报告版本锁定** | 报告归档后锁定版本号与题库／规则／模型／提示词版本快照；修改须新建版本并留痕，历史报告内容不被覆盖 |
| **AI 不诊断的安全边界** | 大模型只做信息采集、结构化抽取、补充性评估与通俗解释；不输出诊断结论、治疗方案与加减停药建议；高风险表述、模型低置信、老人求助时立即提示就医并转人工 |
| **版本留痕** | 评估、匹配、报告全链路保存题库版本、规则版本、模型与提示词版本、报告版本，支持复盘与审计 |
| **冲突不覆盖** | AI 对话信息与量表结果不一致时标记冲突交医护复核，不自动覆盖任一方结果 |

## 术语约定

| 对外术语 | 含义 | 禁用表述 |
| --- | --- | --- |
| **匹配度** | 规则引擎给出的规则可解释分数（0~100） | — |
| **参考概率** | 多候选归一化后的相对可能性（0~100） | — |
| — | — | ~~确诊概率~~、~~患病概率~~、~~疾病概率~~ |

- 对外文案与接口字段统一使用「匹配度」「参考概率」（字段名 `match_score` / `ref_probability`）。
- 所有匹配结果与就医提醒必须附带免责声明：**结果仅供参考，不构成诊断，请及时咨询医生。**

## 重要状态声明：量表与疾病库条目为待评审草稿

- 当前仓库内的 **21 张量表条目**与**老年易发疾病库条目**均为**待评审草稿**，统一标记 `review_status: draft_pending_medical_review`。
- 草稿状态下**不得据此出具正式医学结论**；医护与医学专家须逐条核对 **WS/T 888—2026 附录 B 原文**（及对应指南／文献来源）后审批发布（`review_status: approved`），审批与变更全程留痕。
- 阈值、权重、鉴别要点等规则同样处于待评审状态，正式使用前必须完成评审；演示数据不代表医学结论。
